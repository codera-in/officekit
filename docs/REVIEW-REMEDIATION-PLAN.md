## Sequence and dependencies

1. **Reliability and safety:** R01–R04; R14 establishes regression evidence immediately. No expanded paid release claim until clean installation and bookmark preservation pass.
2. **Truthful scope:** R05 audits all 123 capabilities; R06 builds correct routes/transport; R07 resolves formula depth. Publish only release-verified availability.
3. **Polished complete flow:** prepare/approve R10 mock, then implement R08–R10 together for EMI and one PDF operation. Find → run → export → save → restart → reopen must pass as one journey.
4. **Product services:** R11–R13 with separate licensing, optional analytics, support and update contracts. These do not block local tool execution except entitlement checks for paid tools.
5. **Scale:** R15 incrementally supports expansion to 20–30 verified tools, then 50–70, then the full 123 matrix. Estimates follow clean packaging and capability audit; no invented deadline.

Each work package should become an implementation ticket referencing these IDs, prerequisites and fixtures. No Linear tickets or product implementation are created by this planning review. Close a finding only with source correction plus relevant runtime evidence, not its commit title or a coverage percentage.
