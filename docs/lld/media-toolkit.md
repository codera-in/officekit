# Media Toolkit implementation plan

**Version:** 1.0.125 · Release-profile references removed (S3 commit 3a), 2026-10-21; 1.0.124: Merge approved batch, logo and handoff controls, 2026-10-19.

The consolidated UI was approved with “looks good to me” on 2026-10-19; its durable decision is `docs/ui-research/2026-10-19-approved-media-toolkit.md`. The workbench now separates selected files, per-type settings, and results. A session-only draft per media type supplies each selected-file item's typed operation; saved pipelines retain their existing single-kind constraint. Retry retains other results and submits one failed source. Explicit logos use existing multipart staging and one-job opaque grants. Format selectors consume actual capability formats, including optional FLAC/MP3 and H.264/VP9/x265. Installed handoff discovery is read-only; each result action invokes the existing native save-and-dispatch command with only artifact ID, suggested name, destination and optional installed Shortcut name. No pipeline performs a transfer. Earlier pending-design notes below are historical; global cursor controls and native receipt acceptance remain unfinished.

Audio normalization measures the encoded M4A rather than the pre-encode filter signal. FFmpeg encode/measurement pairs share a 120-second deadline and allow at most three attempts, always reading the original staged source. Output is 48 kHz with the source channel count. Decoded true peak above the -2 dBTP ceiling triggers a lower filter ceiling with a 0.25 dB correction margin; loudness error above 0.5 LU is corrected when peak headroom permits. Logs are private and capped at 64 KiB, output at 64 MiB, and the workspace at 192 MiB. Input demuxers are explicitly limited to supported audio containers; cancellation, invalid/nonfinite metrics, and exhausted peak correction remove owned candidates. The AVFoundation fallback similarly retries from the source based on decoded sample peaks, preserving its distinct -2 dBFS sample-peak contract. Peak-constrained loudness reports an unmet target honestly.

The existing image/video crop operation accepts a rectangle or an oriented `aspectRatio`, with optional `smartCrop`. `engine_media_crop.py` now owns bounded ratio parsing, centered geometry, and saliency geometry for the CLI and typed engines. Recipes resolve dimensions from the current stage rather than persisting one source's pixel bounds. Image geometry follows EXIF display orientation; Vision dimensions must agree with the decoded image dimensions. Saved pipelines retain only the ratio/boolean and remain paused. Rectangle requests keep their previous option and result behavior.

Smart analysis copies a no-follow source through a stable descriptor in 1 MiB chunks to an extra private workspace (up to 64 MiB), then reuses the native bounded process runner with a 20-second deadline, cancellation/termination, private file-backed stdout capped at 4 KiB, and suppressed stderr. Video metadata is bounded before frame generation; the analyzed frame is capped at 2,048 pixels per side, with normalized focus mapped back to the source's displayed dimensions. Analysis and prepared outputs are removed on cancellation/failure, and a completed output is retained only if the job is still active. The additional probe workspace is separately bounded from the existing 192 MiB native conversion workspace.

Inline `pipeline run` accepts `$1` through `$99` in `--name-template`, using capture groups from a successful first-step `if(regex: ...)`. For example, `if(regex: "^IMG_([0-9]{4})") -> convert(to: webp)` with `--name-template 'photo-$1.{ext}'` creates a named WebP copy in the chosen output directory. The existing `{ext}` output-format token must remain last. Missing groups, a negated/unavailable regex context, ambiguous indices, oversized values, path separators, control characters, and unsafe final names fail before publication. Capture values are inserted once and remain literal even when they contain braces, percent signs, or other dollar tokens. Unmatched optional groups expand to empty strings.

Capture-named outputs reuse the private staged-segment and exclusive publication path already used for inline forks. This covers ordinary transformations, forked pipelines, and factor-one byte copies. Each input gets its own capture context; skipped inputs cannot supply another file's name. Saved typed recipes reject capture tokens because they do not retain inline filters. This names the prepared output; it does not rename, move, or overwrite a source file.

Inline PDF `if`/`ifNot` supports `dpiGreaterThan` and `dpiLowerThan`. Both axes of every placed image must satisfy the strict threshold. A bounded PDFium object scan reads pixel dimensions and composed image/form placement matrices; the existing PDF parser supplies page `UserUnit`, which PDFium does not expose. No image pixels are decoded. Scans are capped at 100 pages, 10,000 objects, 15 levels, and the existing 64 MiB source bound; a vector-only PDF has no image DPI and does not match a positive DPI condition. Malformed or incomplete scans do not match. These transient filters remain inline-only.

Output `%i` is one-based per CLI/API/MCP batch and continues per watched-folder grant across accepted jobs. A full queue does not consume a sequence number; a new grant starts at one. Output publication retains exclusive collision handling. Source filename braces and percent signs are literal data during `%f` expansion.

`pipeline run <steps>` accepts a bounded safe subset of the installed Clop DSL and maps it to the typed operation model. Supported steps are `optimise`, `convert(to: ...)`, per-file `crop(aspectRatio: ...)` and `downscale(factor: ...)`, video `capFps(fps: ...)`, PDF `extractPagesAsImages(format: ..., quality: ..., dpi: ...)`, `targetSize(size: ...)` for all four media types, image/video `watermark(image: ..., position: ..., opacity: ..., scale: ...)`, first-step `if`/`ifNot` filters on name substring, exact name, regex, media type, file size, image dimensions, or image DPI, up to three inline `fork()` snapshot steps, `stripExif`, video `removeAudio`, audio/video `changeSpeed(factor: ...)`, and audio `normalize(lufs: ...)`. Image DPI comes from bounded local metadata; PDF image DPI comes from the bounded placed-image scan described above. Missing or invalid DPI does not match a positive condition. Video `convert(to: mp4|webm|x265)` uses host FFmpeg only after private synthetic encode probes succeed: H.264/AAC MP4, VP9/Opus WebM, or software HEVC/AAC MP4. Fixed codec arguments use one thread and local-file protocols; sources are never overwritten. These optional encoders are available to typed jobs, CLI, and MCP but are not shown in the desktop format bar until its reviewed format-selector design is approved. Speed is bounded from 25% to 400%; video speed and watermarking preserve audio tracks, while audio speed exports a separate M4A. Video watermarking uses one explicitly selected local PNG/JPEG/WebP logo, stages it inside the private job workspace, and exports a separate MOV. PDF page export uses the existing renderer's 100-page, 20-megapixel-per-page, 120-megapixel-total, and 128 MiB archive limits; it produces ordered PNG/JPEG entries in one ZIP and must be the final operation. Its output is written only to the explicit CLI output directory. Crop/downscale geometry is resolved from a bounded source read or a file-backed native dimension probe. `capFps` reuses video resize with no-upscale maximum dimensions; the native AVFoundation helper lowers composition frame cadence and retains audio. Watermark settings map to validated placement, margin, scale, and opacity options. Target-size values accept bounded byte counts and decimal/binary units and use the existing fit-size operations. The command accepts 1–8 DSL steps and one media kind per invocation; fork snapshots and the final line publish through exclusive collision-safe copies in the selected output directory. The matching `pipeline add <name> '<steps>' --file-type <type>` form persists supported typed transform steps as paused saved pipelines; dynamic crop/downscale steps, transient filters, fork side effects, and logo paths are not persisted. Shell/script steps, file actions, metadata filters, nested steps, unrecognized options, and unsupported formats fail closed. The mounted-DMG smoke verifies inline crop, downscale, frame-rate cap, audio speed, PDF page export, image/video watermark, target size, combined filename/size filters, missing-DPI fail-closed behavior, saved typed DSL runs, and optional host codecs with source hashes unchanged.
`crop(..., smartCrop: true)` and `crop --smart-crop` use a macOS Vision attention-saliency request on a private, no-follow staged copy of the selected image or video. The validated focus box selects an aspect-ratio crop centered on the salient region; if Vision finds no region, the existing centered crop is used. Source dimensions and crop bounds are limited, and sources remain unchanged. Smart crop is available through the local CLI, inline DSL, typed job/MCP recipes, and saved typed pipelines. Dedicated desktop controls remain pending mock approval.

Inline `crop(longEdge: N)`, `crop(width: N)`, and `crop(height: N)` resolve each source's dimensions and map into the existing no-upscale image/video resize operations. Combining width and height first center-crops to that ratio, then resizes within the requested bounds. `lowerBitrate(kbps: N)` is audio-only and uses the existing local audio optimizer; it estimates the source bitrate with a bounded AVFoundation duration probe, snaps down to a supported rate, and passes through an already-lower-rate source unchanged. Sources are never overwritten.

PDF inline `optimise(encoder: medium|aggressive|lossless)` and `optimise(dpi: N)` select the existing visual rasterization or lossless compression operation explicitly. DPI is bounded from 72 through 300. A no-argument PDF optimize step retains OfficeKit's existing lossless behavior.
Image inline `convert(to: webp|jxl, lossless: true)` selects lossless encoding through the existing typed image conversion. Unsupported format/flag combinations fail validation, and the default lossy conversion omits the optional flag to keep saved recipe output stable.
The first inline `if`/`ifNot` pipeline step now accepts AND-combined filename substring/exact/regex, type, byte-size, image width/height, and minimum-resolution conditions. Regex matching uses Clop-style smart case with length and repetition limits that reject nested or ambiguous repeated groups before running on watched-folder filenames. File-size filters use byte units, and dimension filters inspect bounded local single-frame images; Image/PDF DPI filters use bounded local metadata or placement inspection; copied-by filters remain unavailable because source-application identity is not represented by the file job context.

The CLI now accepts Clop-style `settings schema [query]`, `settings get <operation-id>`, and `settings set <operation-id> <options-json>` commands. They expose only OfficeKit's allowlisted typed operation option schemas and validated per-operation defaults from the existing private store; schema queries match operation IDs and option names, and output is JSON. Existing `--settings` forms remain supported. This is operation-default management, not a proxy for unrelated Clop app preferences.

The Clop-style `downscale --factor` CLI now classifies homogeneous audio batches and routes them through `downscale-audio` in CLI and MCP. The macOS AVFoundation helper reads bounded source duration; the CLI estimates average bitrate from file bytes and duration, scales it by the requested factor, clamps to the supported 32–640 kbps range, then calls the existing typed `audio-optimize` operation to create M4A. Factor one copies original bytes without probing. The MCP preset inventory now includes this preset. The fresh mounted Apple Silicon DMG smoke passed for CLI and MCP: audio outputs decode as M4A, factor-one outputs are byte-identical, and source hashes stay unchanged.

The `crop --aspect-ratio WIDTH:HEIGHT` verb and `crop-aspect` CLI/MCP preset calculate a centered crop for single-frame images or supported video, then call typed `image-crop` or `video-crop`. Ratios are strictly parsed and bounded; source media is staged from the same bounded read used for the job. Mounted-DMG smoke verified a 16:9 MCP image crop and a 1:1 CLI video crop, with source hashes unchanged.

`strip-exif` now accepts homogeneous video batches through the typed `video-strip-metadata` operation. The macOS AVFoundation helper rebuilds a pass-through MOV from video and audio tracks with container metadata cleared; the CLI writes a separate copy and rejects mixed image/video batches. A packaged smoke creates a private title marker, verifies the source retains it, and confirms the prepared copy drops it while retaining decodable video and audio.

The Automation-center mock for opt-in clipboard monitoring and bypass, watched-folder grants and pause, safe sibling output naming, allowlisted pipelines, and recent outcomes was inspected in a new Superset Browser tab and approved by the user on 2026-10-19. The approved controls are implemented in the existing Automation view and covered by the media UI test suite.

Watched-folder output-loop prevention now tracks OfficeKit-published file identities across active grants instead of skipping every filename containing `_prepared`. User-owned files with that text are processed normally, and published sibling copies remain excluded for the session. A regression test verifies both processing and no recursive output creation.

The Clop-style `downscale --factor` CLI supports homogeneous image, video, or audio batches. Video obtains display dimensions from the bundled AVFoundation helper and maps to `video-resize`; audio reads bounded duration, estimates average bitrate and maps to `audio-optimize`. Each preset writes a separate output; factor one writes a byte-identical copy without invoking an encoder. The fresh mounted-DMG smoke covers CLI/MCP image, video, and audio downscaling with output decoding and unchanged-source checks.

H.264 MP4 optimize/fit operations accept a 5–100 compression factor; adaptive video compression selects a bounded balanced factor. Image optimize accepts the numeric range as inverse encoder quality and `compression: "adaptive"` as a bounded adaptive quality choice. Its independent `adaptive: true` option compares bounded local JPEG and PNG encodes, retains PNG when transparency exists, and may change the output extension. Audio optimize maps the 5–100 factor to a bounded supported bitrate; explicit bitrate settings take precedence. Inline pipelines accept `optimise(compression: ...)` and image `optimise(adaptive: true)`. The CLI exposes compression through `--compression` and format adaptation through `--adaptive-optimisation`; all outputs are separate copies.

## Module ownership

AVIF uses Pillow's built-in encoder; JPEG XL uses the optional BSD-3-Clause `pylibjxl` Pillow plugin. Both support conversion, single-frame optimization, size targeting, resize, and metadata removal. Their cached encode probes gate build-specific capability output. Crop and watermark operations may decode modern formats but output JPEG/PNG. DTOs accept AVIF/JXL statically, while the engine rejects output requests when the matching encoder is absent. UI result-format choices come from capability discovery. The packaged sidecar smoke converts a selected image when AVIF/JXL is advertised, checks each container signature, and verifies the source hash is unchanged.

## Contract model

New API requests use strict discriminated DTOs from `engine_media_models.py`:

- `MediaSource`: exactly one of an opaque native `selection_id`, single-use public `import_id`, or single-use staged-image ID. Paths and image bytes are never serialized in media-job requests.
- `MediaOperation`: fixed `operation_id` from the capability catalog plus operation-specific fields. No shell, script, arbitrary codec string, output path, or network URL inside a pipeline step.
- `MediaJobCreate`: 1–30 files, maximum 8 ordered operations per item, optional bounded batch profile. Batch items may have separate media-safe settings; every item returns an independent outcome.
- `MediaJobResponse`: opaque job ID, state (`queued`, `running`, `ready`, `partial`, `failed`, `cancelled`), integer progress, total/completed counts, safe display name, stable error code, output metadata, and short-lived artifact IDs. No absolute path, source data, or parser diagnostics.
- `MediaArtifactResponse`: bytes are streamed from a private app-owned staged file; response is no-store and expires with its owning job.

Initial caps to implement as named constants: 30 files/job, 8 operations/item, 4 active jobs/app, 20 queued jobs, 30-minute per-file execution deadline, and per-adapter input/output/work limits. These apply to the shared media-job route; existing image routes retain their current 64 MiB and 50-image batch limits. Large audio/video caps must be finalized with engine and package feasibility before those adapters are enabled; do not silently raise the existing upload cap.

The implemented preview route accepts only credential-free HTTPS public URLs on port 443, resolves every redirect against public-address policy, pins each validated address during the TLS-verified request, caps redirects/time/bytes, and reads no media body into persistent storage. Preview issues a single-use 5-minute import ID bound to the expected host, media type, length and safe filename. The workbench presents that metadata and only a direct user-initiated Prepare copies job consumes the grant.

## User flow and routing

1. `media_toolkit` opens Images by default and presents file drop/native select, optional URL preview/import, four media modes, and batch queue.
2. Old image tool routes resolve to the same destination with a selected operation: convert, resize, or remove metadata. Search synonyms remain registered.
3. The shared file row reports format, dimensions/duration/pages, and size only when the adapter can read it within bounds.
4. User selects a typed operation, target size/format/dimensions/quality where applicable. Preview/estimate is explicitly labeled estimate until output is generated.
5. Create job against opaque native selection grants. Poll status using the existing activity pattern, enable cancellation only while meaningful, and retain per-file failures.
6. The engine writes to private staging, probes/validates output and caps, then publishes an immutable artifact. User selects a native Save As destination. Existing sources are never overwritten.
7. Screenshot Editor, PDF workbench, and transcription offer a handoff that passes selected result bytes through existing native authority or an opaque temporary artifact ID.
8. Media triggers/settings are implemented only after shared manual operations work. Each automation defaults off; settings persist only explicit operations and opaque folder grants.

## Error and recovery behavior

- `400/422`: show a field/operation-specific safe message; keep source selection/settings intact for correction.
- `403/404`: invalidate stale grants/imports/artifacts and show a reselect/repreview action; never retry the same authority silently.
- `409`: show queue/full/stale/finalization conflict and preserve current per-file outcomes.
- `413/415`: identify the unsupported file/limit without exposing parser/codec diagnostics; keep other batch outcomes.
- `429/503`: retain configuration and offer manual retry after queue/engine recovery; do not re-download or reprocess automatically.
- Cancellation stops a child process when supported, deletes only the staging object whose identity is held, and leaves all originals untouched. A result that entered final publication reports completed or partial and is not described as rolled back.
- Public URL preview/download errors report the host-safe status only; no raw URL query/credentials are logged or persisted. Redirect to a private or changed address fails closed.
