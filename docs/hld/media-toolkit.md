# Media Toolkit

Version: 1.1.56 · Release-profile references removed (S3 commit 3a), 2026-10-21; 1.1.55: Verify packaged aspect-ratio crop parity, 2026-10-19.

Video metadata removal is an allowlisted `video-strip-metadata` operation. The macOS helper composes the source video/audio tracks, performs a pass-through MOV export, and explicitly clears asset metadata. It runs in the existing private bounded workspace; the source remains unchanged and publication uses a new sibling output.

The Clop-style factor downscale command and MCP preset now cover audio alongside image and video. A bounded AVFoundation probe supplies duration; the adapter estimates average bitrate from source bytes, scales it by the requested factor, clamps to the typed audio encoder range, and outputs a separate M4A through `audio-optimize`. Factor one copies the source unchanged without encoding.

The fresh Apple Silicon DMG smoke now passes this path through both the packaged CLI and MCP. It verifies decoded M4A output, byte-identical factor-one output, and unchanged source hashes; notarization is skipped when Apple credentials are absent.

Clop-style centered aspect-ratio crop is available through the local CLI and MCP for single-frame images and supported video. It calculates a bounded integer crop rectangle and uses the existing typed `image-crop` or `video-crop` operation; outputs are sibling copies and inputs remain unchanged.

## Problem and scope

The Automation view lets users set an optional safe output-name template when creating a local pipeline. The same template is applied to manual runs, clipboard preparation, watched-folder jobs, CLI, and MCP. Private local pipeline-trigger bindings let a user pin an existing allowlisted pipeline to clipboard or the general drop zone. Clipboard pins accept image pipelines only and are used by the explicit shortcut; explicit drops run the pinned drop-zone recipe. Bindings store no paths or media.

OfficeKit's image converter, resizer, and metadata remover are separate tools. PDF compression lives in the PDF workbench. Screenshot editing and audio transcription solve different tasks. There is no shared media optimization job/queue, no video/audio optimizer, and no media automation layer. Clop 3.6.0 provides a useful capability reference across images, video, PDFs, audio, batch, size targeting, clipboard/folder triggers, pipelines, hotkeys, CLI/MCP, and external handoffs.

This HLD proposes one OfficeKit Media Toolkit integrated with existing engines and native file authority. It does not add a Clop runtime dependency. The complete user scope and acceptance criteria are in [requirements](../../review/clop-media-toolkit/requirements.md) and [PRD](../PRD.md). Delivery is staged; a capability is not exposed as ready before its engine, bounds, route, packaging, and UI flow exist.

AVIF and JPEG XL output reuse the Pillow converter and are advertised only after the current runtime successfully encodes a bounded 1×1 probe image. JPEG XL uses the optional BSD-3-Clause `pylibjxl` plugin on macOS 14+ and Windows x64 builds. The UI reads output formats from capability discovery, so a package without a codec does not offer that format.

Audio FLAC output uses the system `afconvert` only after a bounded private WAV encode probe succeeds; the catalog omits FLAC when the installed encoder cannot produce it. Optional MP3 output uses a host-installed FFmpeg executable only after a bounded `libmp3lame` encode probe; it is not bundled, its fixed command permits local file protocols only, and it reports lossy MP3 bitrate metadata. FLAC results report `codec: flac` and `lossless: true` without an audio bitrate; M4A alone reports the AAC bitrate. The MP3 selector remains behind its reviewed workbench mock.

Video optimization and fit-size may offer AV1 in MP4 through a host-installed FFmpeg only when `libsvtav1` passes a bounded synthetic encode probe. FFmpeg is not copied into the OfficeKit app. The fixed command uses only an absolute executable from standard Homebrew/system paths, accepts only MOV/MP4/M4V and Matroska containers for AV1 input, disables network protocols, removes source metadata, and runs under the same file, output, workspace, cancellation, and time bounds as the system adapter. AV1 artifacts are verified as MP4 and report `codec: av1`; availability follows the installed encoder.

HEVC conversion uses macOS `avconvert`'s `PresetHEVCHighestQuality` only when that preset is present. It produces a separate HEVC MOV and is independently discoverable from compatible video optimization. The approved conversion design shows a distinct HEVC action, MOV output, compatibility note, separate prepared copy, and unchanged source; approval was received on 2026-10-18 before UI implementation.

## Current state

- `app.py` exposes image conversion, image metadata removal, single resize, batch resize, and PDF operations. Image bytes and decoded pixels have explicit bounds.
- `officekit/engines/engine_file_converter.py` contains bounded image conversion/resizing and metadata handling. Its formats include JPEG, PNG, WebP, BMP, ICO, TIFF, and PDF; animation and multipage behavior is deliberately constrained/preserved by operation.
- PDF compression uses `pikepdf` and named lossless profiles. Existing PDF compression must keep its identity and fidelity promise.
- Media Toolkit now adds a bounded raster-based PDF visual optimizer/size fitter with PyPDFium2 + ReportLab and a vector-preserving centered crop via pypdf. The selected operation displays the fidelity loss and page boundary behavior before execution. Visual output loses searchable text, clickable links, fillable form fields, accessibility structure, and cryptographic signatures; annotation appearances may be rasterized.
- PDF crop accepts a named built-in page target, custom ratio, Clop 3.6.0 device name, or paper-size name through the shared job and pipeline operation contract. The CLI lists device and paper catalogs, can force page orientation, extend page bounds without clipping visible content, and recursively scan a bounded folder tree without following symlinks. All outputs remain vector-preserving copies.
- The typed `pdf-uncrop` operation restores each page's CropBox to its MediaBox in a new PDF copy. The `uncrop-pdf` CLI/MCP preset uses the same operation; it retains searchable text and never writes to the source.
- Screenshot Editor already reads/writes image clipboard content through native/browser bridges and provides editing/annotation operations.
- Voice Transcription and Meeting Notes process audio for recognition/notes; they do not convert/compress audio.
- Existing native file selections, Save As, local API authentication, PDF/file job patterns, Activity reporting, and tool registry provide integration points.
- `API-CONTRACT.md` is the implemented surface. New media job routes must be declared there before client calls are added. No database or cloud processing is needed.

## Approach

Use a shared typed media-job interface on the existing authenticated local sidecar. Reuse image and lossless PDF engines. PDF visual optimization/size-fit and page crop are now separate typed operations. Public HTTPS preview/download now uses a single-use grant, pinned public DNS answers, manual redirect validation, TLS verification, and a bounded response. Add pinned, platform-appropriate media engines behind media-specific adapters for video and audio. A capability catalog is derived from adapters actually present in the packaged build; format buttons and workflow triggers use this catalog rather than claiming a universal format list.

Tauri remains responsible for native selection, scoped folder grants, hotkeys, clipboard monitoring, and explicit destination choice. The opt-in Control+Shift+C shortcut reads an image only after a keypress and remains separate from clipboard monitoring. The Python sidecar performs validated transforms. Large inputs are processed from authorized local files through bounded temporary files rather than being loaded as whole media blobs into memory. Native commands send opaque selection/grant IDs, never arbitrary paths or shell strings from the webview. For OS file drops, the pinned Tauri event bridge omits raw paths and skips webview filesystem grants; only the native Rust handler processes source paths.

### Alternatives considered

1. **Integrated OfficeKit engines (recommended):** preserve the local sidecar and native authority, reuse current engines, add pinned open-source adapters and shared queue. Highest integration/release effort; keeps OfficeKit behavior and portability under its own support policy.
2. **Delegate to installed Clop:** call Clop SDK/CLI for transformations and add OfficeKit navigation around it. Lower media-engine effort, but depends on Clop being installed/licensed, relies on another product's API and settings, and does not cover OfficeKit's Windows/Linux builds.
3. **Keep independent tools and wrap with shortcuts:** add separate Clop-like screens around current engines. Lowest initial integration cost, but duplicates conversion/resizing/compression forms and leaves common batches, results, and automation inconsistent.

The approved mock and owner instruction select the integrated-workbench direction and option 1 for operation ownership. PDF fidelity and URL import mocks were subsequently approved on 2026-10-18. Platform-engine research uses [Apple's AVAssetExportSession documentation](https://developer.apple.com/documentation/avfoundation/avassetexportsession), [FFmpeg's license guidance](https://www.ffmpeg.org/legal.html), [pypdfium2's Python API](https://pypdfium2-team.github.io/pypdfium2/python_api.html) and [PDFium's BSD-style license](https://pdfium.googlesource.com/pdfium/+/refs/heads/main/LICENSE).

## UI composition and route behavior

- New `media_toolkit` route: native file selection, public HTTPS preview and single-use import, Images/Video/PDF/Audio modes, batch queue, progress/cancel, per-operation fidelity guidance, and deliberate Save As.
- Existing Convert Images, Resize Images, and Image Metadata search terms open the Images mode with the corresponding operation selected. During migration their registry IDs are aliases, not separate processing implementations.
- Screenshot Editor remains a separate tool and retains its own edit/copy/save flow. Its explicit “Optimize edited copy” action stages the exported image in an app-private directory under a single-use five-minute grant and opens Media Toolkit with that copy selected. Image structure and dimensions are validated, the staged bytes are deleted after the job or on clear/expiry, and the editor export and original remain unchanged. Editing operations are not duplicated in the optimizer.
- PDF workbench remains for page-level editing, security, OCR, merge/split, and lossless compression. Media Toolkit's PDF mode adds target-size/visual optimization as a separate explicit operation and links to the existing workbench.
- Voice Transcription and Meeting Notes remain separate. Audio mode owns optimization/conversion. Voice Transcription now offers an explicit “Optimize audio copy” handoff that uses the existing read-only native selection grant and opens the selected audio in the shared queue; no path or media bytes enter the webview, and the source stays unchanged.
- Activity receives long-job progress, cancellation, per-file source/output byte counts, size-target outcomes, status, and result links through the existing job reporting pattern.

The base workbench, PDF fidelity warning, and URL import preview mocks were approved by the user. Their durable decisions are recorded here; temporary mock files were removed after implementation.

## Proposed local API surface

All routes use the existing bearer/origin middleware, strict Pydantic DTOs, generic error envelope, and response-size caps. No job route accepts arbitrary filesystem paths, shell commands, raw URLs, or unrestricted scripts. Public URL import is restricted to its explicit preview grant and the Screenshot Editor handoff is restricted to a verified, short-lived staged-image grant.

Automation configuration is local and native-owned. Clipboard image automation is opt-in and defaults off. While enabled, the app polls AppKit's pasteboard change counter; it reads pixels only after a change, accepts bounded images through the existing clipboard bridge, and submits the staged image to the same typed `image-optimize` job used by Media Toolkit. Text is ignored, one changed item can be bypassed, and disabling automation blocks artifact delivery back to the clipboard. The separate Control+Shift+C hotkey is opt-in and reads only an image after a direct keypress. Watched-folder automation requires a native read-write folder grant and explicit pipeline choice; it processes only newly appearing stable files and writes complete sibling copies with exclusive no-replace publication. Folder grants last for the app session, pause/resume and removal are visible, and recent outcomes contain no paths. Named preset-zone bindings map a private zone name to an existing allowlisted pipeline; the local API persists only zone and pipeline IDs, while enabled state stays in memory and resets off at relaunch. Enabled zones register visible native drop bounds only while the Automation view is open; native Rust validates and grants the dropped files, then the webview submits the saved pipeline through the normal local job path. Raw paths never enter the webview. The macOS app bundles `OfficeKit.app/Contents/Resources/binaries/officekit-media`, a native launcher to the same validated local CLI contract. A typed image preset supports Finder handoff without recipe files or shell fragments, while the local CLI also offers a separate `optimize-media` preset that selects one fixed allowlisted operation per common media extension, and an explicit CLI collision policy can publish numbered sibling copies using exclusive no-replace links. Finder integration is a packaged Automator Quick Action installed or removed only after an explicit user action; it accepts images, resolves OfficeKit by its bundle ID, uses argument-vector invocation, and never overwrites an existing workflow. The same executable starts an official SDK stdio MCP server with operation discovery, bounded prepare-files, and strict saved-pipeline listing/creation/rename and explicit execution by recipe ID using the same private local store. Recipes always start paused. MCP returns fixed safe errors and refuses invalid operations. LUFS normalization prefers host-installed FFmpeg `loudnorm` after a bounded probe, with fixed local-file protocols, a -2 dBTP ceiling, measured M4A output and typed true-peak/loudness attributes. When unavailable, the native AVFoundation fallback supports mono/stereo with a -2 dBFS sample-peak ceiling and makes no true-peak claim. FFmpeg is never bundled. Downscale/crop shortcut variants and external integrations remain follow-on capabilities.

Saved pipelines are private local recipes with 1–8 validated operations and one media kind. Their name can be changed through the local API or MCP while the recipe ID and contents remain stable, preserving folder and preset bindings. A preset zone stores only its display name and an existing pipeline ID; its enablement is process-local and resets off at relaunch. The optional watched-folder flow requires a native read-write folder grant and a separately selected saved pipeline. The backend holds the opaque file-selection grant for the watcher lifetime, takes a baseline so existing files are not processed, waits for new files to stabilize across scans, and submits work through the ordinary typed media-job queue. Successful artifacts are atomically published beside the selected source using exclusive no-replace naming; collisions receive numbered suffixes. Pause stops new submissions and lets active jobs finish. Removing the watcher releases the grant. Folder rules and paths are session-scoped and are not persisted; the user grants folders again after app restart. Folder paths remain in the native/backend boundary; responses expose only display names, opaque IDs, and bounded recent outcomes. Approved preset drop UI is implemented; physical drag gestures still require installed-app acceptance. The CLI is available both as `python -m officekit.media_cli` in a source checkout and through the bundled macOS launcher. The bundled MCP stdio server exposes operation discovery, bounded local-file preparation, and strict saved-pipeline listing, creation, and rename through the same typed operation contract. The CLI also exposes schema/list/get/set/clear for the same private typed defaults store used by the app and MCP. All interfaces use bounded processing, batch limits, and exclusive output publication.
Image watermark overlays use an explicitly selected PNG/JPEG/WebP logo staged privately for five minutes (5 MiB, single frame, bounded dimensions). The logo is referenced by an opaque one-job grant, held only while queued/processing, and omitted from recipe persistence and all job results. The image engine composites a scaled logo with placement, edge margin, and alpha controls into the same safe-copy job pipeline; output selection continues through the native Save As flow. The mock is awaiting user approval before the corresponding workbench UI is added.

## Data and privacy

- No database, tenant ID, account, telemetry payload, or cloud transformation is added.
- Saved operation defaults live in versioned browser local storage with a 16 KiB cap and store only typed option values; no filenames, paths, selections, or media bytes are persisted.
- Job state and short-lived artifacts belong to one running app instance and expire when completed/expired under named limits. Persistent automation rules contain operation settings and opaque native grants, not media bytes or copied source files.
- Original files are never replaced by default. Operations write into private same-volume staging or app-private scratch, verify the completed output, and publish with no-replace semantics to a user-selected destination. Batch results are per-file; partial failures are not hidden.
- Logs contain operation ID, stable error code, and coarse progress only. No source path, filename, media metadata, clipboard content, transcript, or payload is logged.
- Clipboard auto-optimization and folder watching default off, require explicit setup, offer pause/disable and retain only bounded operation outcomes. URL fetching is excluded from all automatic triggers and pipelines.
- Upload/shelf integrations are disabled until explicitly connected and triggered. A pipeline cannot fetch arbitrary URLs, add arbitrary network destinations, or execute scripts. The explicit URL import path is a public-HTTPS-only download with DNS/IP checks on every redirect, TLS hostname validation, byte/time limits, no cookies/authorization, and no persistent URL history.

## Resource and platform constraints

- Each adapter declares accepted container/codec combinations, decoded/encoded work limits, file/output limits, timeout, concurrency, and dependency/license metadata.
- Video and audio operations use process isolation/argument vectors, no shell, private temp outputs, bounded stdout/stderr, termination on cancel/timeout, and output probes before publication. Huge assets are streamed; no whole-file memory buffering.
- PDF lossless and visual optimization are different operation IDs. Visual changes show input/output preview and resolution/quality choice, and the text/searchability/readability limitations before execution.
- Limits for large video/audio files, batch counts/bytes, queue depth, and scratch space are finalized after representative Apple Silicon, Intel, Windows, and Linux packaging feasibility. A platform reports unsupported features honestly until that evidence exists.
- Bundled encoder licensing, codec patents, notarization, installer size, and security updates are release gates, not implementation assumptions. Do not add Ghostscript/FFmpeg or a GPL codec until licensing and package provenance are reviewed.
- Engine feasibility research (2026-10-18): Apple's AVFoundation exports only formats supported by the configured session and is a macOS adapter, so the live supported-format catalog must drive availability. The macOS system `avconvert`/`afconvert` adapters are supplemented by a bundled AVFoundation helper for bounded video crop, speed changes, audio-track removal, GIF encoding, and M4A artwork resizing. Normalization prefers host FFmpeg only after a bounded `loudnorm` probe; it processes local files only, bounds resources and reports measured true peak. If unavailable, AVFoundation provides a mono/stereo sample-peak fallback. FFmpeg's official guidance says the base project is LGPL, optional parts can make the build GPL, and redistribution has specific source, notice, configuration, and linking obligations. The Homebrew FFmpeg present on this development Mac is GPL-enabled and is not a distributable OfficeKit runtime. If FFmpeg is selected for broad cross-platform parity, pin the exact build, exclude GPL and nonfree components, publish matching source/notices, audit every linked codec, and complete distribution/patent review before packaging.

## Pitfall controls

- P-004 and P-040: bounded request bodies, decoded work, aggregate batch budgets, and outputs; use streamed/native grants for media larger than current image limits.
- P-041/P-042/P-068: retain lossless PDF behavior, route/profile declaration, and packaged output/fidelity verification; no preset may be a decorative no-op.
- P-046/P-048/P-049/P-051: preserve animation/pages, orientation, supported profiles, and cumulative frame/pixel bounds. Don't broaden formats without actual output read-back.
- P-157: paths are not authority; retain native opaque selection/grant IDs, identity revalidation, no-follow staging, and no-replace publication.
- P-128 and P-081: clipboard access remains an explicit user action/opt-in with correct snapshot and restoration behavior; clipboard failure never loses original data.
- P-167/P-171/P-172: complete workbench/result flows, stable reserved action placement, focus/accessibility, and full registry routes.

## Rollout gates

Saved-pipeline updates are available through the shared local API and MCP store. They replace the name and allowlisted operations within the existing media kind while preserving the UUID and paused state, so existing automation references remain valid. A pipeline may also define a safe output-name template using `{name}`, `{ext}`, and `{media}`; the template cannot include path separators, must end in `{ext}`, and is applied to desktop job results, watched-folder copies, and CLI/MCP runs. Existing saved pipeline files migrate to a null template without losing their definitions. The local MCP inventory includes `officekit_media_update_pipeline` and packaged smoke verifies it alongside the other media tools.

The local MCP surface also supports deleting saved pipelines and managing durable preset-zone name-to-pipeline bindings. Deletion refuses pipelines referenced by a saved zone; deleting a zone removes only that binding. Renaming and rebinding preserve zone identity; rebinding also preserves its name and desktop session enablement. MCP mutation results omit enabled state because the separate process cannot observe it. MCP never grants watched folders or enables native drop targets, which remain controlled by the desktop session. New bindings are persisted disabled.

1. Confirm HLD, engine/license matrix, and numerical resource limits. Do not add a new encoder until provenance is documented. PyPDFium2 is an existing pinned dependency; bundled Homebrew GPL-enabled FFmpeg is excluded.
2. Land shared job/result DTOs, capability reporting, and adapter ownership; verify existing image/PDF routes remain backward compatible.
3. Merge the existing image operations and implement image fit-target, output comparison, batch, and deliberate save flow.
4. Add PDF visual-target mode while keeping lossless separate; validate text, links, forms, image quality, and page geometry.
5. Add video and audio adapters; verify actual containers/codecs, cancellation, A/V synchronization, metadata behavior, and outputs in packaged binaries.
6. Scoped session-only folder watching, preset-zone drop execution, an explicit image-only Finder Quick Action, and native saved-copy handoff commands for Dropshare, shelf apps, and Apple Shortcuts are implemented. Downscale/crop shortcut variants remain. The external handoff UI needs its own approved mock and packaged app behavior checks.
7. Update `API-CONTRACT.md`, the tool registry, `docs/TOOL-GUIDE.md`, and `docs/TESTING.md` whenever each capability is implemented and evidence exists. Source-only support is not a packaged-ready claim.
