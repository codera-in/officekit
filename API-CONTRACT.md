## Ergonomics companion (native, paid feature in every build)

Update 2026-10-22 (S3 review round 1, owner decision "Ship it, paid"): ergonomics ships in all builds as a paid feature behind the licence gate; the five `ergonomics_*` commands are Paid and refuse with `license_required` without a verified entitlement. The development-only gating described in the original approval below is superseded; the companion-window restriction (the companion webview may call only `ergonomics_get_state` and `ergonomics_reminder_action`) remains.

Approved meeting extension: `docs/ui-research/2026-10-21-approved-meeting-countdown.md`. Discovery ID `meeting_countdown` opens the same workbench (a paid feature in every build; see the 2026-10-22 note above). `settings.meetings` defaults to `{enabled:false,allCalendars:true,calendarIds:[]}` for old settings. Strict fields, booleans, max 256 unique nonempty calendar IDs each <=2,048 UTF-8 bytes. `allCalendars:false` with no IDs selects none. Persist IDs, never event contents. Native macOS calendar permission is required to read; OfficeKit never writes events.

`ergonomics_calendar_action({action:"permission"|"privacy"})` returns ErgonomicsState; main window only, Paid. Permission asynchronously asks macOS; privacy opens a fixed system destination; other actions fail. `ergonomics_preview` additionally accepts `meeting` for a 20-second sample sequence without calendar access. `ergonomics_reminder_action` action `done` hides only the current matching meeting occurrence; stale IDs fail; empty-ID `close-preview` closes the sample without hiding live events.

State additionally contains `calendar:{status,calendars:[{id,title}],selectedEvent:null|{id,calendarId,title,calendarTitle,start},preview:boolean}`. Unix-seconds `start`; status disabled/refreshing/allowed/permission-needed/requesting/denied/restricted/unavailable/error/preview. Feed bound 256 calendars, 2,048 events; JS sees only the selected event. Prompt kind `meeting`, phase `ready`/`starting`, opaque occurrence ID and remaining seconds. Show at <=1,800 seconds before start, wave for eight seconds at start, then expire. Poll every ten seconds; 45-second freshness bound. Revoked/invalid/stale feeds hide calendar prompts. Meetings honor quiet hours/pause, take priority, and do not depend on recent keyboard input. EventKit handles recurrence/edits; skip all-day/cancelled/self-declined events. Companion retains its existing two-command IPC allowlist.

Approved 2026-10-21: `docs/ui-research/2026-10-21-approved-ergonomics.md`. Local native commands only; no HTTP route, hosted account, tenant, database table or cloud topology. Preferences belong to the current OS user and are atomically saved in app data as `ergonomics-v1.json`. Raw motion samples and live reminders are never persisted. No data migration is required. New discovery IDs are `ergonomics_break`, `ergonomics_eyes`, `ergonomics_water`, `ergonomics_posture`; all route to modes of the same workbench (the former exclusion from the removed `private-beta` profile no longer applies).

`ErgonomicsSettings` is a strict camelCase object, rejects unknown fields and invalid types, with `version: 1`, `corner` one of `top-left`, `top-right`, `bottom-left`, `bottom-right`, `reducedMotion: boolean`, `quietHours: {enabled: boolean, startMinutes: 0..1439, endMinutes: 0..1439}` with distinct endpoints, `breaks`, `eyes`, `water` objects `{enabled: boolean, intervalMinutes: integer, durationSeconds: integer, snoozeMinutes: 1..60}`, and `posture: {enabled: boolean, dwellSeconds: 5..120, cooldownMinutes: 1..60, snoozeMinutes: 1..60}`. Break interval 5..180 minutes and duration 20..900 seconds; eyes 5..120 minutes and 10..120 seconds; water 5..240 minutes and duration exactly zero. All reminder/sensing enabled flags default false; defaults are breaks 50/120/5, eyes 20/20/5, water 60/0/5, posture 20/5/5, quiet hours enabled 22:00–08:00, bottom-right and reducedMotion false. System reduced-motion preference also applies. Motion enablement is never automatically restored on app launch.

`ErgonomicsState` is `{settings, activitySupported: boolean, pausedRemainingSeconds: integer|null, nextDue: [{kind, seconds: integer|null}], prompt: null|{id: string, kind, phase: "ready"|"active"|"complete", remainingSeconds: integer|null, preview: boolean}, motion: {status, calibrated: boolean, relativePitchDegrees: number|null, relativeRollDegrees: number|null, stable: boolean}, error: string|null}`. `activitySupported` is currently true on macOS; other platforms fail closed and the workbench explains that automatic reminders are unavailable there. For `nextDue.kind === "posture"`, `seconds` is remaining cooldown until another sustained-tilt nudge is eligible; it is null while disabled, paused or quiet. Motion status is `disabled`, `permission-needed`, `denied`, `unavailable`, `calibrating`, `ready`, `disconnected`, `stale` or `error`; finite head-angle values are session-only estimates relative to calibration, never a spine/health score. The `ergonomics:state` event goes only to the main window. The companion has no event-plugin permission and polls only its bounded state/action commands. Sensor enablement is reset on app restart and requires a fresh explicit action. Errors are bounded fixed user messages; no raw sample streams or private source paths.

The Rust scheduler runs independently of WebView timers while OfficeKit runs. One prompt at a time, per-kind intervals/snoozes, break/eye Start countdowns, one-hour Pause all and Resume. Quiet hours and sleep/wake suppress catch-up floods. Timing edits re-arm affected reminders from now. Preview uses the same character/actions but never alters a live schedule. The reminder bubble has a ✕ Close button (and Escape) that sends `dismiss` for break, eye and water prompts, `done` for a meeting prompt and `close-preview` for a preview; Pause all is a text link. During an active eye rest the bubble names three eye exercises (look far away, blink slowly, look side to side) sharing the configured duration, 5 to 10 seconds each, while the mascot keeps its own animation. Corner changes move prompt and character together within a monitor's usable work area without taking keyboard focus. Explicit Quit shuts down the scheduler and motion updates. Native fullscreen/multi-monitor/focus behavior requires installed acceptance; browser animation tests do not establish it.

## Media Toolkit jobs (development profile)

Current desktop integration: the consolidated design was approved on 2026-10-19 (see `docs/ui-research/2026-10-19-approved-media-toolkit.md`). Capability discovery now includes 28 operations, adding `video-watermark-overlay`; only `pdf-pages-to-images` and `audio-speed` remain pipeline-only. Audio format controls follow probed FLAC/MP3 availability, and video controls expose probed H.264 MP4, VP9 WebM and x265/HEVC. Mixed batches submit per-item operations with settings retained per media type. Unchecked files are omitted; retry submits only the failed selected-file source and retains existing result artifacts. One-use logo staging is exposed for image/video overlays. Native handoff controls discover installed destinations and invoke `media_handoff_open` only after an explicit result action; native Save As precedes dispatch. These source changes supersede earlier pending-mock and format-hiding notes below. Packaging and native installed-app acceptance remain separate evidence.

Audio normalization reports measurements of the decoded final M4A, after AAC encoding. The optional FFmpeg adapter preserves channel count at 48 kHz, enforces a -2 dBTP ceiling, and makes at most three attempts from the original source within one 120-second deadline. A peak-constrained result can report `target_met: false`; successful loudness matching requires a 0.5 LU tolerance and the applicable peak ceiling. The AVFoundation fallback measures decoded sample peak and enforces -2 dBFS without claiming true-peak control. Failed or cancelled attempts remove owned candidate outputs and private metrics.

`image-crop` and `video-crop` accept exactly one target form: a complete integer `x`, `y`, `width`, `height` rectangle, or `aspectRatio` with optional boolean `smartCrop`. Ratios use `width:height`, retain orientation, accept up to four decimal places per side, and normalize to bounded reduced integers from 1:10 through 10:1. Rectangle and ratio fields cannot be mixed, even with null rectangle values. `smartCrop: true` requires an aspect ratio. Geometry is resolved from the current pipeline stage, so these options can be stored in paused typed pipelines and used through jobs, CLI recipes, and MCP.

Centered image aspect crops use the displayed EXIF orientation. Smart crops use local macOS Vision saliency on private staged media and fall back to center only when analysis reports no salient region; a missing native helper reports engine unavailability. Results contain resolved dimensions/offsets and, for smart crops, `smart_crop` and `saliency_detected`; no source path or saliency staging path is returned. Rectangle requests retain their existing result shape. Analysis source copying uses 1 MiB chunks, the native analysis process is cancellable with a 20-second deadline and a 4 KiB output cap, and video analysis uses a frame no larger than 2,048 pixels per side while retaining original displayed source dimensions for geometry. Desktop crop controls retain the existing rectangle form pending their approved design.

PDF crop accepts a built-in page size, validated `aspectRatio`, `deviceName`, or `paperSizeName` through the shared typed job and pipeline DTO. Decimal ratio sides may have up to four places; reduced dimensions are capped at 10,000 and ratios at 1:10 through 10:1. The canonical ratio is orientation-adaptive unless `pageLayout` forces portrait or landscape. The local CLI exposes device names with `--for-device`, paper names with `--paper-size`, and lists with `--list-devices` or `--list-paper-sizes`. The device and paper catalogs are derived from Clop 3.5.1; `--extend` grows page bounds and preserves all visible content instead of clipping. `--recursive` scans PDF folders without following symlinks, caps discovery at 30 PDFs and 10,000 directory entries, and excludes the selected output directory. Crop and extend write new output files and never overwrite the source.
The typed `pdf-uncrop` operation and `uncrop-pdf` CLI/MCP preset reset each page's CropBox to its MediaBox in a new copy, restoring content hidden by a prior crop where it exists within the media bounds. Searchable content is preserved and the input file remains unchanged.

The local MCP server exposes the same typed pipeline store for list/create/rename/update/run/delete and durable preset-zone binding list/create/rename/rebind/delete. Preset-zone rename and rebind preserve its ID, and rebind also preserves its name and current desktop-session enablement. MCP mutation results return durable binding fields only because the separate MCP process cannot observe the desktop's in-memory enablement. Pipeline deletion refuses saved preset-zone references; deleting or rebinding a binding changes only automation settings. MCP cannot grant folders or enable native drop targets: those actions remain desktop-session-only, and new bindings start disabled.

Image conversion, optimization, size targeting, resize, and metadata removal advertise AVIF or JPEG XL output only when the packaged runtime passes an actual encoder probe. JPEG XL uses the optional BSD-3-Clause `pylibjxl` Pillow plugin on macOS 14+ and Windows x64 builds; other builds keep it unavailable. Crop and watermark operations can decode modern image inputs but emit JPEG or PNG. `GET /api/media-capabilities` advertises these formats under the same runtime checks.

Routes are implemented in `officekit/media_routes.py`; strict operation and job DTOs live in `officekit/engines/engine_media_models.py`; the app-instance queue and private artifact store live in `officekit/engines/engine_media_jobs.py`. They use the existing bearer/origin middleware and native opaque file selections. Image transforms, image/video watermark overlays, lossless PDF compression, vector-preserving PDF crop, and visual PDF optimize/fit reuse local OfficeKit dependencies. Watermark overlays use one explicit private, five-minute logo staging grant capped at 5 MiB; a job may use it for a batch, and neither source nor logo bytes or paths appear in responses or saved recipes. Video watermark composition is an allowlisted local CLI/MCP pipeline operation; the desktop capability list and workbench controls remain pending their reviewed mock. Visual PDF operations rasterize pages and do not preserve searchable text, clickable links, fillable forms, accessibility structure, or digital signatures; visible annotation appearances may be rasterized. The workbench displays this warning before the job can start. On macOS, video optimize/fit-size use Apple `avconvert` for M4V/MOV and may offer AV1-in-MP4 when a local FFmpeg with `libsvtav1` passes a bounded encode probe. Typed video optimize/fit jobs also accept H.264 MP4, VP9 WebM, and software x265/HEVC MP4 after private synthetic video+audio encoder probes pass; these targets are available through typed jobs, CLI, and MCP but are not advertised in the desktop format bar pending mock approval. FFmpeg is not bundled and receives only fixed local-file inputs with the file protocol; encodes use one thread and bounded private workspaces. Audio optimize/convert/fit-size use `afconvert` for M4A/WAV/AIFF and FLAC after a successful encoder probe; optional MP3 output uses a host-installed FFmpeg only after a bounded private `libmp3lame` probe, with fixed arguments and file-only protocols. Subprocesses are time-limited, output-capped and cancellation-aware. Audio loudness normalization prefers host FFmpeg `loudnorm` after a bounded probe, exports M4A, targets a -2 dBTP ceiling, and reports input/output LUFS, measured output true peak, normalization mode and target status. The probed adapter supports available multichannel layouts. If unavailable, the AVFoundation fallback supports 0.4–120 second mono/stereo sources and reports its -2 dBFS sample-peak ceiling without claiming true-peak control. Public HTTPS previews and job downloads use DNS pinning, redirect validation, TLS verification, a 64 MiB limit, and single-use five-minute import grants; the workbench fetches remote media only after explicit job submission. Media-job item results report source and output byte counts, transformation attributes, and whether a requested size target was met. FLAC outputs use `audio/flac` and report codec/lossless attributes; MP3 uses `audio/mpeg` and reports lossy codec/bitrate attributes. Video crop/speed/mute/GIF/watermark and audio artwork availability follows the installed native helper. `GET /api/media-capabilities` reports the exact per-build transform availability for desktop operations.

Typed H.264 MP4 video optimize and fit-size accept a compression factor from 5 (highest quality) through 100 (smallest output), with adaptive mapped to a bounded balanced factor. Image optimize accepts that numeric range as inverse encoder quality or `compression: "adaptive"` as adaptive quality. Its separate `adaptive: true` option compares bounded JPEG and PNG copies, preserves transparency as PNG, and may change the output extension. Audio optimize maps the 5–100 factor to a supported bitrate; `noUpscale: true` conservatively caps bitrate against a bounded local duration probe and passes lower-rate files through unchanged. CLI exposes `--compression` and `--adaptive-optimisation`; pipeline DSL supports `optimise(compression: ...)`, image `optimise(adaptive: true)`, and audio `lowerBitrate(kbps: ...)`. Outputs remain separate copies.
PDF pipeline optimize accepts explicit `optimise(encoder: medium|aggressive|lossless)` and `optimise(dpi: N)` steps, mapping to the existing visual/lossless PDF transforms. DPI is bounded to 72–300, and visual rasterization remains distinct from lossless compression.
Image `convert(to: webp|jxl, lossless: true)` selects lossless encoding through the shared typed `image-convert` operation; other target formats reject this option, and default lossy recipes omit it for compatibility.
Inline `if` and `ifNot` accept combined safe filename, media-type, byte-size, and image-dimension conditions. Filename regular expressions are bounded, reject dangerous repeated groups, and apply smart-case matching. Image-dimension conditions reject non-image inputs; PDF DPI and clipboard-origin filters are not yet supported.

Saved operation defaults share validated option values between the desktop Automation view and local MCP. The store is private to the current user, capped at 16 KiB, and contains no media files or paths.

Pipeline trigger bindings share an existing saved pipeline with clipboard and the general drop zone. Bindings persist only the target and opaque pipeline ID in a private local store; clipboard accepts image pipelines only. These triggers do not grant filesystem access, and a drop-zone binding runs only for an explicit file drop while the Prepare view is open.

This is a snapshot of routes currently implemented in `app.py` plus the native Tauri IPC
commands declared below, so the client can call declared operations only. It is not evidence that the current Tauri runtime starts the
API or that a tool is production-ready. JSON request bodies use `application/json`;
file inputs use `multipart/form-data`. FastAPI request-model validation returns 422
with a generic detail message; rejected values are not echoed, so non-finite JSON
numbers cannot break error serialization or expose submitted data.
Unhandled exceptions return a generic 500 error envelope; diagnostic details stay in
local server logs and are not returned to the webview. Packaged Tauri sidecars require
a per-launch `OFFICEKIT_API_TOKEN` and a matching `Authorization: Bearer …` header on
every `/api/*` request, including health checks. The token is generated by the native
shell and delivered to the webview through Tauri IPC. A missing token is allowed only
for direct development/test server runs; the packaged sidecar refuses to start without
a valid token. CORS allows the Authorization header and explicitly exposes the OfficeKit
output/input ratio, PDF page count and image width/height headers consumed by the webview.
The API origin guard accepts native requests without an `Origin` header and exact origins for the Tauri webview plus the local Python launcher at `http://127.0.0.1:8000`; other browser origins, ports and host spellings are rejected.

Statement image OCR uses a bundled macOS Vision helper with bounded image dimensions, subprocess time and output; it preserves word positions to separate dates, multiword descriptions and amounts. Other platforms distinguish an unavailable OCR package or Tesseract executable (503) from unreadable image/recognition failures (422) with fixed, safe messages. A successful OCR pass with no rows still returns the existing “No extractable text or tables” 422 response. Raw decoder/OCR details remain server-side only. Scanned-PDF pages with no table or no usable dated vector rows use the same local OCR capability; recovered rows replace vector candidates only when their structural score is higher. A weak vector result is preserved if OCR is unavailable, while a page with no vector extraction retains the safe OCR-unavailable/error behavior. When upright OCR finds no aligned transaction rows or reverses known statement headers, 90-, 180- and 270-degree attempts are scored and selected within the same aggregate pixel and time bounds. CSV uses comma separators and TSV uses tab separators; both accept UTF-8 with an optional BOM, preserve quoted fields and return a safe 422 for invalid encoding or CSV quoting.

Every `/api/*` request body is capped at 8 MiB before DTO parsing by default. Explicit route limits override this for larger uploads, including the 64 MiB document/conversion inputs and 512 MiB workspace multipart import (plus bounded multipart overhead). Workspace JSON `POST` routes remain explicitly enumerated at the same 8 MiB limit so route-inventory tests detect drift.
Malformed `Content-Length` values are rejected unless they contain only ASCII decimal digits; valid leading zeros are accepted. Duplicate length fields and conflicting `Content-Length`/`Transfer-Encoding` framing are rejected before reading the body.

Statement extraction adds `excluded_rows: [{row_index, reason}]` for rows whose mapped date cell contains multiple date tokens. Such rows remain available in `raw_rows` for review but are omitted from `transactions`, `total_transactions`, checked-movement counts and transaction exports; they are included in `unverified_rows` so the screen cannot report a fully verified statement after skipping a possible movement. A skipped row makes reconciliation `partial` (`valid: null`) when at least one other movement was checked, or `unverified` when none was checked; an actual balance mismatch keeps `discrepancy` precedence. `row_index` is the zero-based index into `raw_rows`, and the current reason is `multiple_dates`. The result screen discloses the count and lets users inspect the excluded date and description. This is a fail-closed safeguard, not proof that the rest of a statement was extracted correctly.

Each module declares its pre-parse body caps (`BODY_LIMITS`) and readable response headers (`EXPOSE_HEADERS`), and `app.py` merges both. Each slice adds rows only in its own section. Designs are in `docs/hld/pending-tools-<slice>.md`.

### Pending tools — developer

Development-only routes under `/api/developer` (`officekit/routes/developer.py`). Every POST has a pre-parse body cap, a fixed 422 message per route and no echoed input (P-013). Limits are in code: 1,048,576 UTF-8 bytes per text field (the DTO also rejects more than 1,048,576 code points as a cheap pre-filter, which never accepts more than the byte limit allows), 1,000 UUIDs, 8 target zones, 2,953 QR payload characters.

Work and output budgets (named constants in `officekit/engines/_myers.py` and `officekit/engines/engine_developer.py`):
- `MAX_SEARCH_WORK` = 4,000,000 units per line diff. A unit is one diagonal visit or one snake step in the Myers search. Exceeding it, like exceeding the edit bound, returns the route's fixed 422 without finishing the search.
- `MAX_INLINE_SPAN_WORK` = 4,000,000 units shared by all changed rows of one text diff. Once spent, the remaining changed rows omit `left_spans` and `right_spans`, and the text-diff response sets `spans_omitted` to `true`. The same flag is set when a changed line is over 1,000 code points.
- `MAX_JSON_OUTPUT_BYTES` = 1,048,576 UTF-8 bytes of change paths and previews per JSON compare. A change that would exceed the remaining bytes is counted in `counts` but not listed, and `truncated` is `true`. Paths are never built for unlisted changes.

### Pending tools — image

All routes are development-only and `POST`. Each answers `200` with a derived, unstored result. Image parts accept `.jpg .jpeg .png .webp .bmp .tif .tiff .gif` only (`415` otherwise). Errors use a fixed `detail` and a stable `code`, including framework validation `422`s on these routes, which carry `code` `INVALID_OPTIONS` and the fixed detail `Request contains invalid or unsupported values.` Body caps are per route (`BODY_LIMITS`). `X-OfficeKit-Image-Density` and `X-OfficeKit-Upscaled-Sizes` are readable through `EXPOSE_HEADERS`. The success headers the contract names (`X-OfficeKit-*` and `X-Content-Type-Options`) are declared in the OpenAPI document; `Content-Disposition` on attachment responses is set by the server but is not declared there.

### Restore from Trash (development profile, S06 R1)

Records are written when OfficeKit moves an item to Trash (storage cleanup and the duplicate finder). The ledger is local, 0600, bounded to 10,000 entries and pruned after 30 days. Names and paths are returned only by the local listing and are never logged.

| Route | Request | Response | Notes |
|---|---|---|---|
| `GET /api/trash-records?offset&limit` | `offset ≥ 0` (≤ 10,000), `limit` 1–200 (default 200); no body | 200 `TrashRecordPage` | `state` is `restorable`, `name-taken`, `changed` or `missing`. Read-only; computes states without moving anything. `moved_at` is epoch seconds |
| `POST /api/trash-restore-grants` | Native header `X-OfficeKit-Native-Grant`; `{recordIds: [uuid, 1–100, unique], destinationGrantId?: string}`; a destination needs exactly one id | 201 `TrashRestoreGrant` | Mints a single-use grant bound to the exact ids. The destination is an output grant from `file_output_choose` with `jobKind:"trash-restore"`. Called only by the native confirm command |
| `POST /api/trash-restorations` | Native header; `{recordIds: [uuid, 1–100, unique], restoreGrantId}` | 201 `TrashRestoration` | `restored_to` is the absolute path a restored item was put back at; it is `null` for skipped items. `reason` is `missing`, `changed`, `name-taken` or `protected` for skipped items. Nothing is replaced. The grant is spent before any work; a forged, reused, expired or mismatched grant answers 403 and a mismatch leaves the grant unspent. `restored_bytes` is the sum of restored item sizes; no free-space claim is made |
| `DELETE /api/trash-records/{id}` | Native header; no body | 204 | Forgets the ledger entry only; the file stays in Trash. Unknown id → 404; ledger save failure → generic 422 |

Errors, by route (the body `detail` is one of these fixed messages; no name, path or server text is echoed):
- 422 framework message for DTO violations (unknown fields, bad UUIDs, duplicates, out-of-range bounds, `offset` above 10,000, `limit` outside 1–200).
- 422 `The file operation could not be completed. Check the selection and options.` for a destination on more than one id on the mint route. The same message answers any other engine failure outside the named cases: on the listing for a filesystem error while reading the ledger or folders, on the restorations route for a filesystem error outside the per-item skip reasons, on `DELETE /api/trash-records/{id}` when the ledger cannot be saved, and on the mint route for any other engine rejection.
- 403 `Native restore authorization required` for a missing or wrong native header on any mutating route.
- 403 `Restore approval is missing, expired or does not match these items. Choose them again.` for a restore grant that is forged, reused, expired or bound to other ids. A mismatch leaves the grant unspent.
- 403 `Output grant does not allow this operation` on the mint route when the destination grant is not a trash-restore output grant. The server's own message is passed through.
- 404 `Selection or result is unavailable. Choose it again.` on the mint route for an absent record id or an unavailable destination grant, and on forget for an absent record id.
- 503 `The file queue is full. Wait for an operation to finish and try again.` on the mint route when 32 approvals are already waiting. The destination grant is not spent by that refusal.
- 403 `This operation is not available in the OfficeKit private beta.` on every trash route under private beta.

Native commands (Tauri, webview-invoked, each shows a native dialog before any request): `trash_restore_confirm(items[{id,name,folder}], destinationGrantId?)` returns the restore grant or null when cancelled; `trash_restore_apply(restoreGrantId, recordIds)` posts the restoration; `trash_record_forget(recordId, name)` returns whether the entry was forgotten; `trash_restore_reveal(path)` reveals an absolute, non-link path in Finder.

## Native Tauri IPC commands

These commands are registered by the Rust desktop shell and are invoked through
`window.__TAURI__.core.invoke`. Audio is captured and transcribed locally and never
sent to a server. The `dictation_cleanup_and_paste` command sends only transcript text
and the user's dictionary to the authenticated loopback Python helper for deterministic
cleanup; no remote server is involved.
License activation is a separate explicit network action: it sends the entered key,
app version, platform, device public key and one-use proof to `api.officekit.app`.
The private device key and signed offline entitlement stay in macOS Keychain. The
client refuses activation when build-pinned public keys are absent; configure
`OFFICEKIT_LICENSE_PUBLIC_KEYS_JSON` and `OFFICEKIT_LICENSE_API_BASE_URL` at build
time after the hosted service is deployed.

The native Fn state machine, bounded loopback cleanup client, dictionary validation and
paste command have Rust tests and compile in the macOS arm64 app. They have not been
tested with a real model, microphone, permission grant, held-Fn interaction or
focused-app paste. The approved core-dictation UI is implemented and source-level UI tests cover native command wiring and local dictionary bounds; real model, microphone, Fn and focused-app behavior remain unverified.

## Missing desktop contract

The workspace routes currently cover ZIP extraction, batch rename, exact duplicate
reports, selected-file storage and type summaries, selected-copy similar-image reports and file hashes. The screenshot editor operates only on explicitly uploaded selected image bytes; its screen and clipboard flow remain absent. Video scans still lack scoped operations. Do not send arbitrary host paths to this API. Workspaces exist only for the
sidecar process lifetime and need packaged-client lifecycle verification. The API rejects
untrusted browser `Origin` headers, but this does not authenticate non-browser local
processes. Production origins are limited to the Tauri webview and local launcher. The
Playwright origin (`http://127.0.0.1:19874`) is enabled only when the isolated UI test
origin, UI test token and sidecar API token are all explicitly configured. Tauri source wiring launches a sidecar and loads bundled `dist-ui`; clean-package
build, signing, launch and shutdown still need verification.

## Release boundary

Every row above is only a route inventory. Before a route is released, give it bounded
request sizes, exact input/response DTOs, safe error codes, meaningful domain validation,
tests through the same HTTP transport used by the desktop client, and independent output
verification where it produces a file. Unimplemented routes must not appear as working
tools in the catalogue.

## Hosted licensing API

The hosted licensing and support service is operated privately and is not part of this repository. The desktop client talks to it only through the Tauri `license_*` commands listed above; without it the app runs as the Free edition.
